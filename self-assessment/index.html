Professional Self Assessment

Alondra Paulino Santos

Professional Identity and Career Direction

My interest in computing began long before I understood that it could become a career. In 2003, my family had a Gateway desktop computer with a large monitor and an internet connection that shared the telephone line. During my teenage years, I continued learning how computers worked and built my first computer. Those experiences created a lasting interest in technology, even though my path into college and computer science was not immediate.

Years later, the disruption caused by the COVID-19 pandemic gave me an opportunity to reconsider the direction of my career. I enrolled in an information technology program because I initially believed my strongest interest was in computer hardware and systems. During the second year, I took a Python programming course. Writing code changed my understanding of what I could create with a computer, and I transferred into computer science because it aligned more closely with the work I wanted to pursue.

My professional goal is to work in backend or full-stack software development. I am especially interested in building reliable applications, APIs, databases, and authentication systems that support useful user experiences. The Computer Science program and CS 499 helped me move from completing isolated programming assignments to evaluating software as a complete system.

Growth Through the Computer Science Program

My education changed both my technical abilities and the way I approach unfamiliar problems. Early programming courses taught me to decompose problems, trace logic, use functions and classes, and test whether a solution behaves as expected. Later courses required me to work across application layers, select data structures, connect applications to databases, and explain the reasoning behind design choices.

CS 499 brought these areas together through code review, iterative enhancement, evidence collection, and reflection. Instead of treating an application as finished because it runs, I learned to ask whether inputs are validated, errors are handled safely, a design can scale, an algorithm is appropriate, and another developer or stakeholder can understand the result. I used instructor feedback to strengthen implementation evidence, clarify architectural responsibilities, add testing results, document efficiency with Big-O analysis, and connect technical work more explicitly to the course outcomes.

Course Outcomes

Collaboration and Decision Making

Although the capstone artifacts were individual projects, the work reflects professional collaborative practices. My code review communicated a plan for improvement, and I organized findings so that developers and nontechnical stakeholders could understand both the technical concerns and why the changes mattered. I treated instructor feedback as stakeholder input and revised each solution with clear evidence, contextual comments, descriptive names, validation messages, testing, and design documentation.

Professional Communication

The code-review video explains the condition of the original artifacts and the enhancements I planned. The narratives describe original limitations, implemented changes, testing, and connections to the course outcomes. Diagrams, screenshots, tables, and performance measurements communicate results visually and allow readers to evaluate the improvements without relying on unsupported claims.

Algorithmic Problem Solving and Trade Offs

The enhanced CS 300 course-planning application models prerequisites as a directed graph and uses Kahn's topological-sort algorithm to generate a prerequisite-respecting course order. Its adjacency-list design uses O(V + E) time and space while supporting cycle detection and validation of missing, self-referential, duplicate, malformed, and invalid data. Strict compilation and sanitizer testing provide evidence that the solution handles expected and adverse conditions.

Software Engineering Database Design and Industry Value

The enhanced CS 465 Travlr Getaways application demonstrates a complete customer-inquiry workflow, authenticated administration, protected API operations, validation, error handling, and expanded testing. The enhanced CS 340 animal-rescue dashboard moves filtering, pagination, counting, aggregation, deterministic sorting, and indexed retrieval into MongoDB. Automated tests and before-and-after measurements justify the database design while recognizing index storage and write-maintenance costs.

Security Mindset

Security now influences how I approach requirements, validation, architecture, error handling, authentication, authorization, and publication. The artifacts use layered validation, protected administrative functions, safe error responses, query allow-listing, environment-based configuration, malformed-input tests, duplicate detection, strict compilation, and sanitizers. The public portfolio demonstrates the work without exposing credentials, connection strings, or sensitive values.

How the Portfolio Artifacts Work Together

The Travlr Getaways enhancement shows how I design a full-stack workflow and connect user needs to frontend, API, authentication, and data concerns. The course-planning enhancement shows how I select and evaluate data structures and algorithms when dependency relationships determine correctness. The animal-rescue dashboard shows how database architecture, query controls, aggregation, indexing, and measurement affect application reliability and performance.

Together, these artifacts demonstrate that I can evaluate an existing system, select an appropriate improvement, implement it, test it, document its behavior, and explain why the result matters. They also show that software engineering, algorithms, databases, communication, collaboration, and security are interconnected.

Readiness for the Profession

Completing this degree reflects a long path from my first experiences with a home computer, through circumstances that delayed college, to discovering programming and choosing computer science as my profession. That path strengthened my persistence, willingness to keep learning, and ability to improve a solution until the evidence supports the result.

I am entering the next stage of my career with a stronger foundation in backend and full-stack development, data structures and algorithms, databases, testing, documentation, and secure design. My most important ability is not familiarity with one framework. It is the ability to learn, evaluate a problem, communicate with the people affected by it, make defensible design choices, and verify that the implementation works.
